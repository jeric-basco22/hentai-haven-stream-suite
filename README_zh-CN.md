# Haniverse

*一个精心打造的生态系统，用于探索、整理并分享充满深度与情感的手绘视觉叙事作品。*

## 概览

## 概览

Haniverse并非单纯的媒体聚合工具——它更是为插画叙事爱好者精心打造的数字栖息地。鉴于现有工具往往将视觉叙事视为可随意丢弃的商品，Haniverse重新定义了这种体验，将其转化为一种有目的的档案保存方式。每一个故事都应拥有这样一个场所：在这里，元数据、社区见解与视觉精度能够和谐共存，互不冲突。

该仓库包含了用于构建界面、自动化流程以及策划工具的核心框架，这些工具可通过经过严格类型定义且文档完善的 API 层与视觉叙事存储库进行交互。无论您是正在打造个人藏书的收藏家、分析艺术趋势的研究人员，还是致力于设计画廊体验的开发者，Haniverse 都能提供基础架构，帮助您将零散的内容整合为有序的集合。

## 核心理念

每一个视觉叙事都值得拥有一个能够体现其背景脉络的归宿。

在数字领域中，充斥着大量无主文件与失效链接。Haniverse正是为应对数字世界的无序混乱而诞生的。它并非将每件艺术作品视为独立的个体，而是保留艺术家、系列、角色、类型、语言、发布日期以及用户注释等各要素之间的关联网络。这种基于关联的处理方式，让原本扁平的收藏集合蜕变为一个充满活力的动态档案库。

我们的核心原则是“有目的的保存”：我们不会盲目囤积，而是有计划地进行整理。该API会强制执行架构验证，确保每个条目都包含有意义的元数据而非空字段。在需要对数千个条目进行搜索、筛选或生成推荐时，这种严谨的做法能带来显著优势。

## 核心功能

## 核心功能

### 🧬 深度元数据架构
每个条目都支持超过40个字段，涵盖多语言标题、备用命名规则、艺术家签名、圈子标识、登场活动以及内容描述等。该架构可通过自定义字段进行扩展，且不会影响现有查询的运行。

### 🔍 语义搜索引擎
超越简单的关键词匹配。Haniverse通过标签、描述及用户注释采用加权向量搜索技术，根据社区互动程度与元数据完整性来优先呈现最相关的结果。

### 🌐 内置语言层
界面字符串、标签分类体系以及用户生成的内容均支持原生国际化处理。该框架能够自动检测浏览器的语言偏好，并无需手动切换即可提供相应的翻译内容。

### 📱 响应式用户界面组件
专为图库、详情页及搜索界面预构建的 React 组件，能够灵活适配从 320px 的移动端屏幕到超宽 4K 显示器的各种分辨率。每个组件都提供了用于屏幕阅读器和键盘导航的无障碍功能接口。

### 🔄 同步协议
针对需要在本地收藏与远程数据源之间维护同步的用户，Haniverse提供了冲突解决策略——合并、覆盖或标记以便人工审核。时间戳与校验和可有效防止重复数据被导入。

### 🛡️ 请求速率限制与缓存机制
内置的指数退避算法与智能缓存功能可有效减少重复请求。缓存层在从本地存储响应高频查询的同时，还会遵守数据源端的速率限制规则，从而将响应时间提升多达300%。

## 架构概览

Haniverse采用模块化、面向服务的架构设计：

```
haniverse-core/
├── api/
│   ├── endpoints/        # RESTful路由定义
│   ├── middleware/       #身份验证、日志记录、速率限制功能
│   └── serializers/     #数据转换与校验逻辑
├── models/
│   ├── narrative.py     #核心实体定义
│   ├── collection.py    #分组与标记逻辑
│   └── metadata.py      #自定义字段支持
├── engines/
│   ├── search/          #向量和文本搜索实现
│   ├── curation/        #去重与数据增强处理流程
│   └── sync/            #冲突解决与批量处理功能
├── ui/
│   ├── components/      #可复用的React组件
│   ├── themes/          #浅色/深色模式及自定义配色方案
│   └── locales/         #翻译文件（en、ja、ko、zh、es、fr、de、pt、ru、ar）
└── tools/
    ├── cli/             #用于批量操作的命令行工具
    └── dashboard/       #基于Web的监控界面
```

各服务通过共享的事件总线进行通信，从而实现独立的扩展能力。API层为无状态设计，具备水平扩展性。

## API设计原则

## API 设计原则

### 带类型标注的响应
每个接口都会返回包含类型定义的结构化 JSON 数据。无需再猜测某个字段是字符串还是整数。相关架构规范会与代码仓库一同发布，以便用于代码生成工具。

### 可重试操作
当提供唯一标识符时，用于创建或更新记录的 POST 请求即为可重试操作。这样一来，即便网络请求出现重试情况，也能避免生成重复记录。

### 基于游标的分页
无需页码。Haniverse采用不可见游标式分页机制，即便在两次请求之间有新记录添加，也能保证查询结果的一致性。

### 错误处理
每个错误响应都会包含易于人类理解的错误信息、机器可识别的错误代码，以及用于调试的追踪标识符。无需再猜测请求失败的原因。

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "字段‘artist’必须是字符串类型，但当前值为null。",
    "trace_id": "hvn-a3f8c2e1"
  }
}

## 策展引擎

## 策展引擎

策展引擎是 Haniverse 的核心，它能够自动执行以下操作：

- 通过标题的感知哈希值与视觉指纹来**去重**条目。  
- 通过交叉引用已知的艺术家标识符和活动目录来**丰富**数据稀疏的记录。  
- 标记出可疑的元数据（例如不合常理的日期、不匹配的系列等），以便人工审核。  
- 基于内容分析及社区使用模式来**生成**推荐标签。

该引擎既可以针对现有收藏以批量模式运行，也能在新条目加入时实时处理。所有操作都会被记录下来，并且可以撤销。

## 多语言框架

Haniverse 开箱即支持10多种语言，同时还有社区维护的其他语言版本。其本地化系统涵盖：

- **UI字符串**：导航文本、按钮文字、错误信息、帮助说明。  
- **元数据字段**：类别名称、标签分类体系、内容描述词。  
- **搜索索引**：分词时会尊重汉字字符边界、阿拉伯语从右到左的排版方式以及带重音的拉丁字母字符。

要添加新语言，只需提供一个包含键值对的 JSON 文件即可，无需进行任何代码修改。
