# Haniverse

*手描きの視覚的物語を探求し、整理し、共有するための、深みと情緒に満ちた厳選されたエコシステム。*

---

## 概要

Haniverseは単なるメディア集約ツールではありません。それは、イラストを用いた物語作りを愛する人々のために丁寧に構築されたデジタル空間なのです。既存のツールが視覚的な物語を使い捨ての商品として扱っているという認識から生まれたHaniverseは、この体験を意図的で体系的なアーカイブ作業として再構築しています。すべての物語には、メタデータ、コミュニティの知見、そして高品質なビジュアルがスムーズに共存する場所が必要なのです。

このリポジトリには、厳格に型付けされかつ十分にドキュメント化されたAPIレイヤーを通じて視覚的ナラティブのリポジトリと連携するインターフェースや自動化パイプライン、クリエーションツールを構築するためのコアフレームワークが収められています。個人のコレクションライブラリを構築するコレクターであれ、芸術的傾向を分析する研究者であれ、ギャラリー体験を開発するデベロッパーであれ、Haniverseは散在するコンテンツを一貫性のあるコレクションへと変えるための基盤的なアーキテクチャを提供します。

## コア哲学

**あらゆる視覚的な物語には、その背景を大切にする場所が必要です。**

デジタル空間には、取り残されたファイルや機能しないリンクが溢れています。Haniverseは、このようなデジタルエントロピーに対する解決策として生まれました。各アートワークを孤立したものとして扱うのではなく、アーティスト、シリーズ、キャラクター、ジャンル、言語、公開日、ユーザーによる注釈といった関係性のネットワークを保持します。この関係性重視のアプローチにより、単なる平面的なコレクションが生きたアーカイブへと変わります。

私たちの指針は「意図的な保存」です。無差別にデータを蓄積するのではなく、目的を持って整理を行います。APIはスキーマ検証を実施し、空のフィールドではなく意味のあるメタデータが各エントリーに含まれていることを保証します。このような厳格な管理により、何千ものエントリーの中から検索したり、フィルタリングしたり、おすすめを生成したりする際に大きな効果が得られます。

## 主な機能

## 主な機能

### 🧬 深層メタデータアーキテクチャ
各エントリーでは、多言語のタイトル、別名表記、アーティストの署名、サークル識別子、イベント出演歴、コンテンツの説明文など、40以上ものフィールドをサポートしています。また、カスタムフィールドを追加することでスキーマを拡張可能であり、既存のクエリの動作に影響を与えることはありません。

### 🔍 意義ベースの検索エンジン
単なるキーワードマッチングを超えます。Haniverseは、タグ、説明文、ユーザーによる注釈全体に対して重み付きベクトル検索を適用します。結果は、コミュニティでの活動度やメタデータの完全性を基準に、関連性の高い順に表示されます。

### 🌐 内蔵型言語レイヤー
インターフェースのテキストやタグの分類体系、ユーザー生成コンテンツはネイティブに国際化されています。このフレームワークはブラウザの言語設定を自動で検出し、手動で切り替えることなく適切な翻訳を表示します。

### 📱 レスポンシブなUIコンポーネント
ギャラリー、詳細表示、検索インターフェース向けに事前に構築されたReactコンポーネントは、320pxのモバイル画面から超広画角の4Kディスプレイまで柔軟に対応します。各コンポーネントには、スクリーンリーダーやキーボード操作に対応するアクセシビリティ機能も備わっています。

### 🔄 同期プロトコル
リモートソースと併せてローカルにコレクションを管理するユーザー向けに、Haniverseはマージ、上書き、または手動確認のためのフラグ付けといった競合解決戦略を提供します。タイムスタンプやチェックサムにより、重複したデータの取り込みが防がれます。

### 🛡️ レート制限とキャッシング
組み込みの指数関数的バックオフ機能およびインテリジェントなキャッシングにより、不要なリクエストが削減されます。キャッシュ層はソース側のレート制限を尊重しつつ、ローカルストレージからの頻繁なクエリに対応し、応答時間を最大300％まで短縮します。

## アーキテクチャの概要

Haniverseはモジュール型でサービス指向のアーキテクチャを採用しています：

```
haniverse-core/
├── api/
│   ├── endpoints/        # RESTfulルートの定義
│   ├── middleware/       # 認証、ログ記録、レート制限機能
│   └── serializers/     # データの変換および検証処理
├── models/
│   ├── narrative.py     # コアエンティティの定義
│   ├── collection.py    # グループ化やタグ付けのロジック
│   └── metadata.py      # カスタムフィールドのサポート
├── engines/
│   ├── search/          # ベクター検索およびテキスト検索の実装
│   ├── curation/        | 重複排除や情報強化のパイプライン
│   └── sync/            # 冲突解決およびバッチ処理
├── ui/
│   ├── components/      # 再利用可能なReactコンポーネント
│   ├── themes/          # 明るい/暗いモードやカスタムパレット
│   └── locales/         | 翻訳ファイル（en, ja, ko, zh, es, fr, de, pt, ru, ar）
└── tools/
    ├── cli/             | バッチ操作用のコマンドラインユーティリティ
    └── dashboard/       | ウェブベースの監視インターフェース
```

各サービスは共通のイベントバスを介して通信するため、独立したスケーリングが可能です。APIレイヤーはステートレスで、水平方向にスケーリングできます。

1. **構造の維持**：元のMarkdownのデータ構造、インデント、見出し階層、表、リンク、URL、バッジ、コードブロック、およびインラインコードを一切変更しないこと。
2. **選択的翻訳**：ユーザーに表示される可視的な自然言語コンテンツのみを翻訳すること。

4. 用語、文体、固有名詞の翻訳は、提供された背景情報と一致させること。

## API設計の原則

### 型付きレスポンス
すべてのエンドポイントは型定義を含む構造化されたJSONを返します。フィールドが文字列なのか整数なのかを推測する必要はありません。このスキーマはコード生成ツール向けにリポジトリと共に公開されています。

### 再実行可能な操作
一意な識別子が提供されている場合、エントリの作成や更新を行うPOSTリクエストは再実行可能となります。これにより、ネットワークの再試行が発生しても重複したレコードが作成されることがありません。

### カーソルを利用したページネーション
ページ番号はありません。Haniverseはカーソルベースの非透過型ページネーションを採用しており、リクエストの間に新しいエントリが追加されても一貫した結果が得られます。

### エラー処理
すべてのエラーレスポンスには、人間が読みやすいメッセージ、機械が判読可能なコード、およびデバッグ用のトレース識別子が含まれています。リクエストがなぜ失敗したのかを推測する必要はありません。

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "フィールド『artist』は文字列でなければなりませんが、nullが返されました。",
    "trace_id": "hvn-a3f8c2e1"
  }
}
```

## キュレーションエンジン

キュレーションエンジンはHaniverseの核心です。これにより自動的に以下の処理が行われます：

- タイトルや視覚的フィンガープリントの知覚ハッシングを利用してエントリーの重複を検出します。
- 既知のアーティスト識別子やイベントカタログと照合することで、情報が不足しているレコードに詳細情報を追加します。
- 疑わしいメタデータ（例：不自然な日付、一致しないシリーズなど）をマークして、人間による確認を行います。
- コンテンツ分析やコミュニティの傾向に基づき、推奨されるタグを生成します。

このキュレーションエンジンは、既存のコレクションに対してはバッチモードで、新しいエントリが追加されるたびにリアルタイムで動作します。すべての操作は記録され、元に戻すことも可能です。

## 多言語フレームワーク

Haniverseは初期状態ですでに10以上の言語に対応しており、さらなる言語についてはコミュニティによって維持管理されている翻訳が利用可能です。このローカライゼーションシステムは以下をカバーしています：

- **UI文字列**: ナビゲーション、ボタン、エラーメッセージ、ヘルプテキスト。
- **メタデータフィールド**: カテゴリ名、タグの分類体系、コンテンツの説明情報。
- **検索インデックス作成**: トークナイゼーションでは、漢字・日本語・中国語の文字境界、アラビア語の右から左へのレイアウト、およびアクセント付きのラテン文字が尊重されます。

新しい言語を追加するには、キーと値の対で構成されたJSONファイルがあれば十分で、コードの変更は一切必要ありません。

## レスポンシブなUIツールキット

このUIツールキットには、事前に最適化されたコンポーネントが同梱されています：

| コンポーネント | 説明 |
|-----------|-------------|
| `NarrativeCard` | サムネイル、タイトル、アーティスト、タグを表示します。グリッドレイアウトを自動で調整します。 |
| `DetailPanel` | フルなメタデータ、関連するエントリ、ユーザーのメモが記載されたスライドアウト型のオーバーレイです。 |
| `SearchBar` | 最近の検索履歴、提案内容、音声入力によるフィードバックを備えたオートコンプリート機能があります。 |
| `FilterDrawer` | 日付、言語、アーティスト、コンテンツの評価、カスタムタグによる多次元フィルタリングが可能です。 |
| `CollectionManager` | ドラッグ＆ドロップによる整理、一括操作、CSV/JSON形式へのエクスポート機能を提供します。 |

すべてのコンポーネントはテーマに対応しており、アクセシビリティのために高コントラストモードもサポートしています。

## サポートとコミュニティ

Haniverseでは、リポジトリのイシュートラッカーを通じて報告された重大な問題に対して**24時間以内の対応**を保証しています。非重大な機能要望や質問については、毎週レビューが行われます。

コミュニティチャンネルには以下が含まれます：
- クリエイションワークフローを共有するためのディスカッションフォーラム
- 翻訳調整用のスレッド
- ユーザーが作成したインターフェースを紹介するセクション

すべての貢献者は、リリースノートにて名前が記載されます。
